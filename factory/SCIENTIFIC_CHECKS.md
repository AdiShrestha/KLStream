# What local Factory 3.3.1 checks

The active profile is binary classification using Python's isolated standard-library
runtime. Native streaming, GPU execution, dependency environments, malicious-worker
isolation and separately controlled holdouts are unsupported. Unsupported requests
fail; agents must add reviewed adapters rather than fabricate compatible evidence.

Freeze authenticates declared input hashes, a domain-separated SHA256 tree root,
policy-code identity and local key identity. Run and audit share canonical ordered
argv. Execution receipts bind complete metadata and output inventory, including
binary outputs. An authenticated attempt ledger records local dispatches; failed
attempts require amendments, and missing recorded attempts block audit. Directories
are ordinary local filesystem state, not physically immutable storage.

The child gets a bounded environment. Loader/startup hooks are refused; signing-key
variables and unrelated project credentials are omitted. The recorded environment
includes PYTHONHASHSEED, but Python -I ignores it: this is not a hash-randomization
guarantee. Methods must consume the registered algorithm seed explicitly. Resource
policy checks reject unsupported network, memory and process-count enforcement.
Wall timeout kills the launched process group. Wall time is measured; unavailable
CPU/RSS observations are null. This is not a hostile-process containment boundary.

Accepted classification predictions join unique sample IDs, labels, source IDs,
groups and splits to the frozen cohort. Group/time rules are checked under the
declared profile. Probability mode computes AUROC, average precision, accuracy,
F1, Brier and clipped natural-log loss (fixed epsilon 1e-15); ranking mode omits Brier and log loss and accepts finite
unbounded ranking scores. Single-class AUROC fails as undefined. Constant scores
remain calculable with ties, rather than being replaced to manufacture variation.
Training checks match deterministic or iterative policy; registered fixed-budget
nonconvergence is diagnostic unless convergence is claimed. Early-stopping budget
exhaustion is a registered cap outcome; signed finite objectives are minimized. Numeric floors are
schema constraints and declared policy, not evidence of adequate precision.

Paired bootstrap and sign-flip calculations are conditional on the declared aligned
units and fixed corpus. They cannot establish that those units are independent.
Holm correction applies to the registered comparison family. Offline event latency,
offered-ID conservation and censoring still require the future streaming adapter.
Current hardware rows separate aggregate service rate and completion rate over an
explicit inference horizon; neither substitutes for offered-load throughput.

Static scans expand declared code directories. Python AST and lexical diagnostics
are limited defenses; other languages require semantic review. They cannot prove
input authenticity, honest fitting or absence of label copying. Plausibility checks
inspect supported nested values and reject malformed numbers; chance heuristics
are limited to applicable ranking metrics. Negative results remain valid.

Audit assurance is STRUCTURALLY_VALIDATED, SUPERVISOR_ATTESTED or BLOCKED. Verified
local receipts establish the second state; same-user access to keys/inputs means
it is not sealed evaluation. A current review may allow a scoped READY report
status, without changing assurance or proving independent review. Registry checking
verifies test definitions, not execution; executed-suite receipts are separate.
Standalone bundle checks establish byte/local-signature integrity only.
