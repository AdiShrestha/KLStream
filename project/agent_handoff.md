# Start here: Architect and Implementor

Read root `plan.md`, `docs/ENGINE_CONTRACT.md`, `docs/audit/AUDIT_SCOPE.md`, the active
factory constitution/specifications and the assigned contract. You need no access
to the old folder to understand this plan. The audit inventories and excerpts
preserve file identities and defect evidence; legacy code stays in preserved Git
references and is never silently imported into active experiments.

Architect: begin with KLS-01/KLS-02 and a literature-backed KLS-03 feasibility memo.
Keep `project/research_plan.json` invalid/unfrozen until the actual streaming adapter,
cohort, acquisition provenance, commands, calibration, independent units, claims
and fixed selection rules exist. Challenge the implementation before freeze.
Maintain a claim ledger and numbered amendments; disclose prior test exposure.

Implementor: implement one concrete contract at a time with preconditions, source
paths, exact outputs and failure-reproducing tests. Keep the engine independent of
labels, expected effects and paper language. Mark test fixtures at producers and
prevent them entering research evidence. Use `--parallel 2` for builds. Retain
failed attempts and diagnostics; report measured numbers only from executed tools.
Do not treat repeated seeds as additional market days or hardware machines.

Each `project/contracts/KLS-XX/report.md` must record: input hashes, changes, executed
commands and exit statuses, artifact hashes, passed/failed/unexecuted checks,
residual risks, and the next gate. A sentence saying COMPLETE is not acceptance.
Architect reviews raw inputs before the report conclusion. Same-model review is
recorded as such. No agent may claim a factory gate is repaired solely because its
unit tests pass; KLS-02 requires adversarial full lifecycle acceptance tests.

Factory 3.3.0's existing workflow is retained. This plan supplies domain requirements
and documents defects; it does not claim those requirements are already executable.
Add the streaming adapter, language-aware scanning, native runtime, receipt
verification and honest assurance transitions before freeze/run/audit/certify.
Version the changes and retain old policies. Do not lower gates to make KLStream pass.
No fake epoch loss curves, synthetic replacement market data, manually filled
benchmark values, unearned INDEPENDENT review or fabricated READY status.

The research objective is honest knowledge. A null effect, negative controller,
limited domain, failed replication or unresolved data-access blocker must stay
visible. Proceed with independent engineering while a necessary resource is missing;
request the user's help only for that resource or a real scope/permission decision.
